     2 ЗАВДАННЯ
     У межах цього практичного заняття переді мною стоїть завдання детально дослідити ключові стандарти написання чистого, ефективного й підтримуваного коду на мові програмування Java. Необхідно практично опрацювати правила форматування, конвенції іменування, організацію архітектурної структури Maven/Gradle проєктів, а також принципи документування через Javadoc та інструменти статичного аналізу. Окрім цього, завдання передбачає підготовку фрагментів коду на Java, демонстрацію рефакторингу з переходом від громіздких циклів до сучасного Stream API, а також опис циклу TDD та CI/CD пайплайнів.


     3 ОПИС ВИКОНАНОЇ РОБОТИ
     Під час виконання практичного заняття було детально досліджено ключові стандарти, правила та конвенції оформлення програмного коду для мови програмування Java. Згідно з вимогами офіційних рекомендацій Oracle Code Conventions та сучасного посібника Google Java Style Guide, було опрацьовано базові засади написання чистого, ефективного та підтримуваного коду. Візуальні матеріали, архітектурні схеми проєктів та ілюстрації етапів розробки оформлено у вигляді презентації (див. додаток Б, рис. Б.1 — Б.3).
     На першому етапі практичної реалізації було досліджено організацію архітектурної структури каталогів Maven/Gradle проєктів (див. додаток Б, рис. Б.2). Стандартизований розподіл код-бази на шар контролерів, сервісів та репозиторіїв у директорії src/main/java, винесення модульних тестів у src/test та використання конфігураційного файлу pom.xml забезпечують дотримання принципу єдиної відповідальності та можливість автоматизованого збирання. Для дотримання стилю форматування (див. додаток Б, рис. Б.3) було впроваджено використання рівно 4 пробілів для відступів, обмеження довжини рядка до 100–120 символів та застосування стилю розміщення фігурних дужок K&R.
     Окрему увагу було приділено конвенціям іменування та документуванню. На основі розробленого базового класу UserService (див. додаток Б, рис. Б.4 та додаток В, п. В.1) продемонстровано коректне використання регістрів: формат CamelCase для класів та інтерфейсів, camelCase для методів і змінних, а також верхній регістр UPPER_SNAKE_CASE для констант. Для автодокументування публічного API (див. додаток Б, рис. Б.6) було застосовано спеціалізовані блоки Javadoc із тегами @param, @return та @throws. Для автоматичного контролю стилю на рівні збирання проєкту (див. додаток Б, рис. Б.7) було налаштовано інструменти статичного аналізу коду, такі як Checkstyle та PMD, що дозволяє виявляти стилістичні відхилення ще на етапі написання коду.
     У межах дослідження інженерних процесів було розглянуто методологію розробки через тестування (Test-Driven Development, TDD) (див. додаток Б, рис. Б.8), яка базується на триступеневому циклі створення тесту, що падає, написання мінімального коду та подальшого рефакторингу. Також було проілюстровано роботу автоматизованого CI/CD пайплайну (див. додаток Б, рис. Б.9), де після виконання команди Git Push сервер збирання автоматично запускає компіляцію через Maven, перевірку стилю лінтером та фінальне розгортання додатку.
     Завершальним етапом роботи став практичний рефакторинг коду. Традиційний підхід із використанням громіздких імперативних циклів for та вкладених умов if має високу цикломатичну складність і є складним для читання й підтримки (див. додаток В, п. В.2). Завдяки застосуванню сучасного декларативного Stream API (див. додаток Б, рис. Б.10 та додаток В, п. В.3) той самий алгоритм фільтрації та перетворення даних стає лаконічним, безпечним та прозорим для сприйняття. Повний набір розведених фрагментів та комплексний демонстраційний клас об'єднано в єдину структуру й завантажено до репозиторію (див. додаток В, п. В.4).
     


     4 ВИСНОВКИ
     Під час виконання практичного заняття було досягнуто поставленої мети та закріплено навички роботи зі стандартами написання якісного програмного забезпечення, зокрема розглянуто офіційні правила і конвенції оформлення коду для мови Java, включаючи правила форматування за стандартом Google Java Style Guide та конвенції іменування (CamelCase, camelCase, UPPER_SNAKE_CASE). Також було здобуто практичні навички проектування архітектурної структури Maven/Gradle застосунків, документування публічного API за допомогою механізму Javadoc та налаштування інструментів статичного аналізу коду, освоєно методологію розробки через тестування (TDD) і принципи автоматизації перевірки якості коду у складі CI/CD пайплайнів, а також отримано навички проведення ефективного рефакторингу програмного забезпечення шляхом заміни складних імперативних циклів на чистий, декларативний Stream API, що знижує цикломатичну складність та підвищує супроводжуваність кодової бази.

     В.3 Приклад програмного коду після рефакторингу
     GitHub репозиторій: https://github.com/NureViterDmytro/ark-pzpi-24-5-viter-dmytro/blob/main/Pract1/pzpi-24-5-viter-dmytro-pract1/RefactoringComparison.java
1 package org.example;
2 
3 import java.util.Arrays;
4 import java.util.List;
5 import java.util.stream.Collectors;
6 
7 public class RefactoringComparison {
8     public static void main(String[] args) {
9         List<Integer> numbers = Arrays.asList(5, 12, 18, 3, 22, 9, 30);
10 
11         // Після рефакторингу (декларативний Stream API)
12         List<Integer> newResult = numbers.stream()
13                 .filter(n -> n != null && n > 10)
14                 .map(n -> n * 2)
15                 .filter(processed -> processed < 50)
16                 .collect(Collectors.toList());
17 
18         System.out.println("Результат: " + newResult);
19     }
20 }
